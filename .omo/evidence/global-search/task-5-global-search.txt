Findings recorded (not deviations, no product change):
- The `transactions` table has only `created_at` (migration line 96) and the `Transaction` model does not disable
  `updated_at` (unlike `Payment`, which sets `UPDATED_AT = null`), so `Transaction::create()` writes a
  non-existent column. The provider only reads the table; the test fixture inserts with `$model->timestamps = false`.
  The model is outside this task's scope and was not modified.
- No `toResult()` reads a relation (order label = `order_no` accessor on its own column; subtitles = own
  `domain_name` / `status` / `subject`), so no eager loads were added; each provider costs exactly 1 query.
- `OrderSearchProvider` overrides `rankColumn()` to `order_number` explicitly (the base default would also pick
  the first searchable column; the override locks the intent).

## Adversarial probes

### 1. Malformed input — literal `%` identifier

- Test `test_a_literal_percent_in_a_billing_identifier_is_matched_literally`: seeds `INV-50%` and `INV-200`
  (2 rows), queries `q=%`; asserts exactly 1 result, label `INV-50%`, SQL contains `ESCAPE '!'`, and the
  bindings contain `%!%%` — i.e. the query never degenerates into a full-table dump.
- Probe observables above: `WILDCARD_INVOICE_LABELS=["INV-50%"]` with `WILDCARD_ROW_COUNT=2`; the generated
  SQL names `ESCAPE '!'` on every LIKE and the bound pattern is `%!%%`.
- The escaping itself comes from the shared `LikePattern::contains()` + `whereLikeEscaped()`; the providers
  never build LIKE strings by hand.

### 2. Misleading success — exact URLs and payload shape, not substring matches

- All five happy-path tests assert `assertSame(route('admin.<entity>.show', $model), $result['url'])` and
  `assertSame(<identifier>, $result['label'])`, so a swapped destination or a wrong row fails.
- `test_billing_typeahead_payload_never_contains_monetary_fields`: all five groups matched (`assertCount(5)`),
  every result has exactly `['id','label','subtitle','url']`, and none of the seeded monetary values
  (9876.54 / 1234.56 / 543.21 / 321.45 / 654.32) appears in `json_encode($groups)`.
- `test_a_viewer_with_only_customers_view_gets_zero_billing_groups`: all five rows match `ACME`, yet the
  explicit five-provider registry returns `[]` — all five providers skipped.
- `test_transactions_and_quotes_are_gated_by_invoices_view_never_payments_view`: direct `permission()`
  assertions plus a functional run — a `payments.view`-only viewer sees the payments group but none of
  transactions/quotes/invoices/orders.
