## Implementation notes (contract compliance + deviations)

- **Contact URL (the wrong-id-binding trap):** `toResult()` never passes the contact model into the customer route.
  It resolves `route($this->showRoute(), $model->customer)` — the parent customer — and falls back to
  `route('admin.customers.index')` when the relation is absent (explicitly tested with `setRelation('customer', null)`).
  The URL is eager-loaded (`with('customer')`) so rendering N contacts is 1 query, not N.
  No plan column/route name differed from reality; no silent drops. The fallback branch is an addition mandated by the
  task spec (plan line 152 says only "destination the parent `admin.customers.show`").
- **Staff exclusion:** `whereNot('role', 'client')` compiles to `where not "role" = ?` with binding `["client"]`
  (probe output below) and runs BEFORE the LIMIT, so client rows never consume result slots.
  **NULL-role semantics:** the SQL `NOT (role = 'client')` would also drop a NULL role, but a NULL role cannot exist —
  `users.role` is `enum(...)->default('client')` and NOT NULL (`database/migrations/0001_01_01_000000_create_users_table.php:18`),
  and the probe's NULL-role insert is rejected by the database itself (observable below). No NULL-role user is silently
  excluded in practice.
- **Icons:** `bi bi-people` (customers) and `bi bi-person-badge` (staff) mirror the existing menu icons; contacts use
  the Bootstrap Icons `bi bi-person-lines-fill` (no existing contacts menu entry to mirror).
- **Ranking:** `ContactSearchProvider` and `StaffUserSearchProvider` override `rankColumn()` to `email`; customers keep
  the default (first column = `company`). The contact override is behaviourally proven by
  `test_contact_ranking_prefers_the_email_column` (an email-identifier row outranks an exact first-name row; with the
  default `first_name` ranking the assertion would fail).
- **Escaping:** every match goes through the shared `applyTermFilter()` → `whereLikeEscaped()`; no provider builds its
  own LIKE, so `ESCAPE '!'` and the grouped closure are guaranteed by construction.

### 1. Malformed input (LIKE wildcards)

Raw probe on sqlite `:memory:` (temp-dir script, never the local DB):

```
$ $env:DB_CONNECTION='sqlite'; $env:DB_DATABASE=':memory:'; php <temp>\task4_identity_probe.php

NULL-role insert rejected: Illuminate\Database\QueryException: SQLSTATE[23000]: Integrity constraint violation:
  19 NOT NULL constraint failed: users.role

EXIT: 0
```

Test-level observables (`test_a_literal_percent_is_matched_by_q_percent_without_a_full_table_dump`):
- generated SQL contains `ESCAPE '!'`, binding `%!%%` for `q=%`;
- exactly ONE row is returned — the customer whose company holds a literal `%` (`Save 50% Now`, asserted by id) —
  and NOT the ordinary row (`No Discount Here`); `q=%` never degenerates into a full-table dump;
- the same through `GlobalSearchService::groups()` with the real permission set.

### 2. Misleading success output (exact strings, row identity)

- `test_contact_result_url_is_the_parent_customer_show_page` asserts the EXACT string
  `route('admin.customers.show', $parent)` and additionally `assertNotSame(route('admin.customers.show', $contact), …)`.
  The fixture creates two customers so the parent's id (2) and the contact's id (1) differ — a wrong-id URL would fail,
  not merely be non-empty.
- `test_staff_user_is_found_by_email_and_by_name` asserts the exact `route('admin.users.show', $staff)` URL and
  `route('admin.users.index', ['search' => …])` list URL.
- `test_client_accounts_are_excluded_from_the_staff_provider` seeds a client AND a staff row with equally matching
  emails and asserts the returned row id is the staff one — proving matching still runs (not a vacuous empty result).
- `test_contact_group_eager_loads_the_customer_relation_for_its_url` reads `DB::getQueryLog()`: `<= 3` queries
  (1 permission pluck + 1 contact query + 1 eager load); a lazy `$model->customer` in `toResult()` would add a 4th.
- `test_customer_is_absent_for_a_viewer_without_customers_view` and
  `test_a_viewer_with_only_tickets_view_gets_no_identity_groups` read the query log too: `<= 1` query
  (the single permission pluck) — no provider query runs at all for a forbidden viewer.
