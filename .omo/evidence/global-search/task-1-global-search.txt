## Implementation notes (contract compliance)

- `LikePattern::contains('100%_!') === '%100!%!_!!%'`; the escape character is escaped first so a
  literal `!` still matches.
- `whereLikeEscaped()` emits exactly
  `whereRaw($query->getGrammar()->wrap($column)." LIKE ? ESCAPE '!'", [$pattern])`:
  column wrapped by the grammar (never interpolated), pattern bound, ESCAPE named explicitly
  (MySQL's default is a backslash, SQLite has none).
- Grouped WHERE: every column is OR'd inside ONE closure, relations match via `orWhereHas` with their
  own grouped closure — no `orWhere` outside a grouped closure, no `orWhere` leak into caller scoping.
  Verified in the generated SQL below.
- Ranking is SQL-side and applied BEFORE the LIMIT:
  `ORDER BY (CASE WHEN LOWER(col)=LOWER(?) THEN 0 WHEN LOWER(col) LIKE ? ESCAPE '!' THEN 1 ELSE 2 END), id DESC`.
  Deviation from the plan's sketch (which omitted `ESCAPE '!'` on the ranking LIKE): the ranking reuses
  the escaped pattern, so it must name the same ESCAPE character — without it `q=%` would rank by
  "contains !" instead of a literal percent. Same contract, correct escape semantics.
- Route guard: `Route::has($this->showRoute())` or the provider returns an empty collection and logs
  `Log::warning` exactly once per route name (process-static set); never throws.
- Registry: `config/search.php` pre-lists all 17 provider FQCNs. `GlobalSearchService::providers()`
  skips entries that do not exist yet (`class_exists` + `is_subclass_of`), logging once per class,
  never throwing — the 16 classes still to be created in todos 4-7 do not break anything today.
- Query budget: `permissionNames()` is ONE query (pivot roles + legacy `users.role` fallback inside a
  single grouped `where`); `groups()` fetches `limit + 1` per provider for the capped count, so no
  `COUNT(*)` is ever issued.
- Tests register a SINGLE stub provider (`new GlobalSearchService([StubProvider::class])`) — the
  constructor accepts an explicit provider list and falls back to `config('search.providers')`.

## Adversarial probes

### 1. Malformed input (LIKE wildcards)

Raw probe, app booted with sqlite `:memory:` so the developer's local DB was never touched
(probe script lived in the pre-approved temp dir, outside the repo):

```
$ $env:DB_CONNECTION='sqlite'; $env:DB_DATABASE=':memory:'; php <temp>\search_probe.php
LikePattern::contains("100%_!") = %100!%!_!!%
LikePattern::contains("%")     = %!%%
SQL fragment                   = "ticket_no" LIKE ? ESCAPE '!'
Provider registry count        = 17
PROBE_EXIT: 0
```

Test-level observables (from `GlobalSearchServiceTest`):
- generated SQL contains `ESCAPE '!'` and the binding `%!%%` for `q=%`;
- `q=%` returns exactly the one ticket whose number holds a literal `%` (`TKT-50%`) and not the
  ordinary row (`TKT-200`) — i.e. the query never degenerates into a full-table dump;
- `LikePattern::contains('100%_!') === '%100!%!_!!%'`.

### 2. Misleading success output (query counts, not log lines)

All query-budget claims are asserted from `DB::getQueryLog()`:
- `test_a_single_stub_provider_yields_one_group_within_the_query_budget`: `<= 3` queries for the whole
  request (1 permission pluck + 1 provider query + 1 eager load); the assertion message prints the
  captured SQL on failure.
- `test_groups_fetch_one_extra_row_to_report_a_capped_count_without_a_count_query`: asserts the
  captured SQL contains no `count(*)`.
- `test_a_blank_term_returns_no_groups_and_runs_no_provider_query`: `<= 1` query (the permission pluck;
  no provider was asked).

These assertions are live, not vacuous: on the first implementation attempt the run reported
`{"result":"failed","tests":11,"passed":7,"failed":4}` — the tests caught a grouped-WHERE bug (columns
were AND-joined, so `TKT-ACME` matched nothing) and a fixture bug (the seeded `marketing` role's
permissions leaked through the `users.role` fallback, which is real `hasPermission()` semantics and is
now handled by the shared `CreatesChatUsers` test concern). Both were fixed before the green run.
