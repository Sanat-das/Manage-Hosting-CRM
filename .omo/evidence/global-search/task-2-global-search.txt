## Manual QA channel (real executable surface)

The plan's QA scenario (`tinker` against the developer's `local` MySQL) is **forbidden by the DB-safety rule**. Substitution and why: the same end-to-end check was executed against a **disposable scratch sqlite file** (`storage/qa-task2-scratch.sqlite`, deleted afterwards), where `migrate:fresh --seed` is safe — this is the sanctioned smoke pattern (`composer seed:smoke` uses the identical approach). A one-off bootstrap script (`%TEMP%\opencode\qa-task2.php`, deleted afterwards) printed the actual booleans and row counts via the real Eloquent models; the script's first JSON key is the connected DB name, so the output itself proves it did not touch the local DB.

```
$env:DB_CONNECTION='sqlite'; $env:DB_DATABASE='storage/qa-task2-scratch.sqlite'
php artisan migrate:fresh --seed --force --no-interaction      -> exit 0
php qa-task2.php
{
    "db": "storage/qa-task2-scratch.sqlite",
    "support->hasPermission(search)": true,
    "staff->hasPermission(search)": true,
    "roles_with_dashboard_view": ["admin","editor","marketing","sales","staff","support","viewer"],
    "all_dashboard_roles_have_search": true,
    "search_permission_label": "Use Global Search",
    "pivot_before": { "total": 187, "search": 7 }
}
php qa-task2.php --idempotency                                  -> exit 0
{
    "pivot_after": { "total": 187, "search": 7 },
    "pivot_unchanged": true
}
```

`--idempotency` re-runs the migration `up()` **twice** and the real `AdminLteRbacSeeder` **twice** on the same scratch DB. Pivot totals are identical before/after; the search pivot holds exactly 7 rows = the 7 roles holding `dashboard.view`.

Cleanup receipt: `Test-Path storage/qa-task2-scratch.sqlite` -> `False`; `Test-Path %TEMP%\opencode\qa-task2.php` -> `False` (both deleted after the run).
