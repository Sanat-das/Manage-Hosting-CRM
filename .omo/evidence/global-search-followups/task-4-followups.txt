## Tests added (all in the extended foundation suite)

| Test | Proves |
| --- | --- |
| `test_a_service_instances_manage_only_viewer_gets_the_service_instances_group` | viewer holding ONLY `service-instances.manage` gets the `service-instances` group |
| `test_a_hosting_manage_only_viewer_gets_the_hosting_server_and_ssl_groups` | `hosting.manage` alone yields `['hosting', 'servers', 'ssl']` (the multi-provider pair) |
| `test_the_manage_expansion_does_not_leak_across_domains` | `catalog-products.manage` grants no Customers group; `customers.view` grants no servers group |
| `test_the_manage_expansion_stays_one_query_and_preserves_exact_names` | `DB::enableQueryLog()` -> exactly 1 query; the set contains `hosting.manage` + `hosting.view` + `customers.view`; a set with no `.manage` name returns unchanged (`['customers.view']`) |

Design note (per the plan): the rule stays service-local with cross-reference comments in both files rather than a shared resolver class — the middleware is an auth path and extracting the rule would change no behaviour. Direction is one-way (`.manage` -> `.view`); nothing widens `.view` -> `.manage`.
