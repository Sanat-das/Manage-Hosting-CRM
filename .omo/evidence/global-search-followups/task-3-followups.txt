## Debugging note (recorded because it shaped the test)

The first version of the rendering test asserted `assertSessionHasErrors('q')` on the 302 and then issued a follow-up `GET` for the page. It failed: **`assertSessionHasErrors()` consumes the flashed bag in this app's test setup**, so the follow-up GET rendered no error slot. Proven with a temporary diagnostic test (deleted afterwards):

```
R1 status=302   session errors = {"default":{"format":":message","messages":{"q":["The q field must not be greater than 100 characters."]}}}
R2 status=200   marker=YES   is-invalid=YES          <- no assert between the two requests
R4 302 + assertSessionHasErrors('q'); R5 status=200  marker=NO   <- assert between them eats the flash
```

Fix: the rendering test now uses `followingRedirects()` — exactly what a browser does — so the followed page renders the flashed error in the same request cycle, and the session assertion lives in its own separate test.
